# UI translations

h4rn's interface is available in English, Simplified Chinese (`zh-CN`), Spanish
(`es`) and Japanese (`ja`). English is the source language. The person picks a
language under **Settings → Appearance → Language** (System, English, 简体中文,
Español, 日本語). System uses the first browser or OS language h4rn has, and
English when it has none. The choice is saved on this device under
`h4rn.locale` in local storage, like the theme, and applies at once without a
reload. `<html lang>` follows the active language.

The work is split by UI area, one pull request each, so each area can be
reviewed by itself.

## How it works

- The library is [i18next](https://www.i18next.com/) with
  [react-i18next](https://react.i18next.com/), pinned to exact versions in
  `apps/ui/package.json`.
- The code lives in `apps/ui/src/lib/i18n/`. `index.ts` sets up i18next, the
  saved choice, `<html lang>` and the `Intl` formatters. The catalogues are in
  `locales/<language>/<namespace>.json`.
- There is one **namespace per UI area** (`settings`, `sidebar`, and later
  `composer`, …), plus `common` for words many areas share: Save, Cancel,
  Delete, Remove, Copy, Retry, the permission modes and so on.
- `commands` holds each keyboard command's one name (`commands:names.<id>`,
  keyed by `CommandId`) and group heading (`commands:groups.<group>`). The
  command palette, Settings → Shortcuts and the Keyboard shortcuts dialog all
  read them through `commandName` and `commandGroupName` in
  `lib/keybindings.ts`, so a command's name is translated in one place and a
  new command without a name fails `bun run typecheck`. The palette's own rows
  that are not a command (Switch harness…, Hide sidebar, …) live under
  `commands:palette`.
- A place in the app has one name everywhere. The sidebar's names are the
  source: `sidebar:inbox`, `sidebar:footer.*` (Pull requests, Issues, Usage,
  Settings) and `sidebar:hosts.title`. The phone's tab bar (`PhoneNav`) reads
  the same keys; only its pull requests tab uses the shorter
  `sidebar:phoneNav.pulls` ("PRs") so five tabs fit on a phone.
- English ships in the main bundle. Each other language loads as its own
  chunk when someone picks it, before the first render when it is the saved
  choice, so a non-English reader never sees English flash first.
- Keys are checked by TypeScript (`i18next.d.ts` types the catalogue from the
  English JSON). A missing or misspelled key fails `bun run typecheck`.
- A key with no translation falls back to English, never to the raw key.
  An empty value is kept as is, not replaced by English: a scope with no
  second line, or the space between sentences that Chinese and Japanese
  leave out (`settings:worktrees.sentenceSeparator`). The catalogue test
  allows `""` only where English is empty too or for that separator.

## Adding a string

1. Add the English text to `locales/en/<namespace>.json`, nested under the
   page or component it belongs to, for example
   `settings.json → worktrees.remove.title`.
2. Use it in a component with
   `const { t } = useTranslation(["settings", "common"]);` and then
   `t("worktrees.remove.title")` or `t("common:cancel")`. Outside React (a
   store, a validator, a toast), use `i18n.t("settings:worktrees.remove.title")`
   from `@/lib/i18n`; the component that shows the result re-renders on a
   language change because it uses `useTranslation`.
3. Use interpolation for values: `"Remove {{name}}"` with
   `t("…", { name })`. Never build a sentence by joining strings.
4. For counts, use plural keys and pass `count`: English needs `_one` and
   `_other`, Spanish `_one`, `_many` and `_other`, Chinese and Japanese only
   `_other`. The catalogue test checks each language has exactly its forms.
5. For markup inside a sentence (code, a link, bold), write tags in the text
   (`"Run <code>{{command}}</code> in a terminal."`) and render it with
   `<Trans t={t} i18nKey="…" components={{ code: <span className="q-mono" /> }} />`.
   Don't name a tag after an HTML void element (`link`, `img`, `input`,
   `br`, …): the parser closes it at once and the text spills out after it.
6. Format dates, times, relative times, durations and numbers with the helpers
   in `@/lib/i18n` (`formatDateTime`, `formatRelativeTime`, `formatAge`,
   `formatDuration`, `formatClock`, `formatClockUnit`, `formatNumber`,
   `formatList`). They use `Intl` with the active language. `formatClock` is
   the compact, padded figure for a countdown or a table cell ("2m 05s",
   "1h 30m"); `formatClockUnit` is one amount of one unit ("450ms", "1.7s").
   How each language writes those units is a `Locale → units` map in code,
   not a catalogue string: Chinese and Japanese put their own unit word right
   after the number with no space ("2分05秒", "1小时30分", "1時間30分",
   "450毫秒", "450ミリ秒"), and every other language uses Intl's narrow units
   ("2min 05s" in Spanish). Never put a Latin "ms" or "2m05s" inside Chinese
   or Japanese text. `formatAge` is the one-unit age for a narrow column
   ("now", "5m", "3h"; "5分钟" in Chinese); word the direction around it in the
   catalogue ("wakes in {{age}}").
   An age inside a sentence ("opened by alice 3 hours ago") uses
   `formatRelativeTime` and passes the whole phrase in, as `{{when}}`. Don't
   wrap `formatAge` in a hand-built "{{age}} ago" or "{{age}}前": Japanese
   would read "3h前" with a Latin letter instead of "3 時間前".
   Join a list of names with `formatList`, never `", "`: Chinese and Japanese
   use 、. In a table cell, pass the `narrow` style
   (`formatList(names, "conjunction", "narrow")`) so it reads "a, b, c".
7. A store that shows progress or a status keeps a **kind**, not words, and
   the component turns the kind into text: `remoteStore` keeps
   `busy: { kind: "waitingForApproval" }` and `ConnectSignIn` renders
   `settings:connect.busy.waitingForApproval`.
8. Add the translation to `zh-CN`, `es` and `ja` in the same change, using
   the glossary below.
9. A status glyph's `label` (`AgentGlyph`, for example the footer's
   connecting orb) is also its hover `title`, and its screen-reader name when
   `labelled` is set. Translate it like a tooltip, even where nothing shows it
   as text.
10. A count shown in the text is formatted for the language as well as
    pluralised: write `{{count, number}}` in the catalogue (still pass the raw
    `count`), and pass other numbers through `formatNumber`.

Text that comes from the daemon (errors, skip reasons, model names) is shown
as the daemon sends it. Only the copy around it is translated.

## Adding a language

1. Add its code to `LOCALES` and its own name to `LOCALE_NAMES` in
   `lib/i18n/index.ts`, and teach `matchLocale` which system tags map to it.
2. Create `locales/<code>/` with every namespace file, translated in full.
3. Run `bun run test`. The catalogue test fails until every key and plural form
   is present.

## Guards

- `lib/i18n/catalogue.test.ts`: every language has exactly the English keys,
  the plural forms its own `Intl.PluralRules` uses, no empty values, and the
  same `{{placeholders}}` and tags as English.
- `lib/i18n/hardcoded.test.ts`: the files listed in `CONVERTED` have no
  hard-coded user-facing English. It flags JSX text, literals rendered as JSX
  children, read attributes (`aria-label`, `title`, `placeholder`, `label`, …),
  toast, option and error-object `title`/`description`/`label`/`message`
  fields, store fields named `error`, `…Error` or `notice`, a rendered template
  that interpolates a store value as is (`` `${busy}…` ``), and lists joined
  with a hard-coded `", "`. URLs, paths, identifiers and product names are let
  through. Each area PR adds its files.
- A `", "` join that feeds data rather than display (an editable field's
  value, a request body) opts out with a comment on the line above it:
  `// i18n-ignore-next-line: <why>`. The reason is required, and the escape
  covers only that join, never other text.
- The same check flags prose the client writes into an error
  (`throw new Error("…")`), because its message reaches a store's `error`
  field or a toast as is. Translate it where it is thrown, with values as
  placeholders (`i18n.t("sidebar:hosts.errors.noNoiseKey", { name, command:
  "h4rnd login" })`). An internal check that can only fail on a bug (a reply
  of the wrong type, an unknown typed id) opts out with the same
  `// i18n-ignore-next-line: <why>` on the line above it.

## What stays English for now

- **Keycaps.** Shortcut keycaps (⌘ ⇧ ↵, Ctrl, Shift, Alt, Esc, Tab, Space)
  read the same in every language, in the palette, Settings → Shortcuts and
  the Keyboard shortcuts dialog. The palette searches each row's English name
  and English synonyms as well as the translated name, so typing "settle" or
  "diff" keeps working after a language switch.
- **Thread titles, host and project names in the palette** are shown as they
  are.
- **Pairing codes and links.** The pairing code, the code field's
  `ABCD-EFGH` shape, the comparison code, host and device names and
  the relay's address are shown as they are. The link countdown keeps its
  `m:ss` form.
- **What the agent and the daemon wrote.** Messages, tool names, tool
  input and output, file names, diffs, a change set's note, a subagent's task
  and error, terminal output (including its "[process exited …]" line) and
  daemon error codes in the thread's Details are shown as written. The shell
  name a new terminal tab starts with ("zsh") is a program name.
- **The right panel's Files and Preview tabs and the IDE** are converted with
  their own areas.
- **Usage figures and provider text.** Model ids, harness names, account and
  provider labels, a limit's provider message, the daemon's failover reasons
  and its "nowhere to fail over" reason are shown as sent. The unit `tok/s`
  and the column name TTFT stay as written. A provider message that names a
  limit's window ("5-hour", "weekly") is read for that window, which is then
  worded in the language. Durations use `formatClock` (see step 6): "2m 05s"
  in English, "2分05秒" in Chinese and Japanese. Costs are US dollars with
  the narrow "$" in every language ("1,23 $", never "US$1.23"), in the
  figures and on the chart's axis alike.
- **MCP health in the Settings sidebar.** The Tools list's health words
  (`serverStatus` in `features/mcp/labels.ts`) are converted with the MCP and
  skills pages.
- **Thread action failures.** "Settling failed on atlas." and the other
  `runThreadAction` toasts in `appStore` are shared with the thread view and
  belong to "Connection banner, toasts and errors raised outside Settings".
  That includes a failed model, mode, effort or Fast change from the
  composer's picker ("Changing the model failed on atlas."); the picker itself
  is translated.
- **Confirmation text is the caller's.** `ConfirmDialog` translates only its
  own Cancel; the title, body and button are the caller's text. Every current
  caller translates its own, and a new caller must too.
- **Messages a store writes for these dialogs.** The guest sharing store's
  errors and the project import scan's errors come from stores and belong to
  "Connection banner, toasts and errors raised outside Settings". The dialogs
  show them as they arrive.
- **The skills and MCP pages.** Only their dialogs are converted. A skill's
  source label (`sourceLabel`) is shared with the Skills page, so that page
  shows it translated before the rest of the page.
- **Code in examples.** Placeholder examples that are code (`-y
  @modelcontextprotocol/server-github`, `search, read_file`, a git URL) and
  the transport names stdio, HTTP and SSE read the same in every language.
- **Model names and agent modes.** Model ids, and an effort level an agent
  names itself that h4rn does not know, are shown as sent.
- **Forge and tracker data.** Pull request and issue titles, bodies,
  comments, labels, branch names, authors, check names and descriptions, a
  linked pull request's own state word on the issue pane, and Linear's state
  names are shown as the forge or tracker sends them. The Labels and Assignees
  fields on the issue pane hold comma-separated text that is split on commas
  when saved, so they keep `", "` in every language; the read-only list of
  assignees above them uses `formatList`.
- **Daemon text.** Errors, hints and names the daemon or a forge sends are
  shown as sent; see above.

## Glossary

Use these terms in every area so a word means the same thing everywhere.
Working, Done and Settled are the three thread states (`docs/ux.md`), not
folders: Settled is not "archived". A state's **label** is singular in Spanish
(«En curso», «Terminado», «Resuelto»), and a state named inside a sentence is
quoted the language's way: "Mantener en «En curso»", 保留在“进行中”,
「作業中」に残す. Shared words for the states live in `common:states.*`.

## Translation guidelines

- Write for developers. Keep the tone of the English: short, plain, precise,
  no exclamation marks.
- Keep product terms as names: **h4rn**, **Connect** / **h4rn-connect**,
  **worktree**, **harness**, **Labs**, **CLIProxyAPI**, **MCP**, **ACP**, and
  third-party names (Claude Code, Codex, GitHub, Linear, Tailscale).
- Keep commands, flags, environment variables, scopes and code
  (`h4rnd login`, `H4RN_GITHUB_CLIENT_ID`, `Contents: read`) exactly as written.
- Follow each platform's UI conventions:
  - **zh-CN**: full-width punctuation (，。：“”), no trailing full stop on short
    labels, a space between Chinese and Latin words or numbers. A thread is
    对话 and a session is 会话.
  - **es**: sentence case, «comillas» for quoted names, and address the reader
    as *tú*, as common developer tools do. A thread is *hilo*.
  - **ja**: です/ます style for sentences, plain nouns for labels, full-width
    punctuation and 「」 quotes. A thread is スレッド.
- Spanish runs about 30% longer than English; keep labels short so rows do not
  wrap on a phone.
- The Working / Done / Settled segment never wraps. When a language's labels
  are too long for the sidebar's width (Spanish at the narrowest 240 px), the
  labels shrink with an ellipsis, the counts stay, and each tab's full name
  moves to its tooltip (`StateTabs`, `.q-seg.fit`). At wider sizes and in the
  other languages the tabs look exactly as in English.
- The thread view follows the same rule. The right panel's tabs (Changes,
  Files, Preview, Subagents) sit closer together in a narrow panel, then
  shrink with an ellipsis at the 320 px minimum, with the full name in their
  tooltip. The thread header's state word ("Requiere aprobación") gives way
  before the header's buttons, on a phone and on a narrow desktop, and keeps
  the whole label as its tooltip.
